# Сборка, проверки и восстановление

## Что именно сохранено
`v36/` — авторские скрипты и тесты точного checkpoint test02; `mission_port36/` — выборочные исследовательские инструменты; `v34/symbols.json`, `v35c/symbols.json`, `v36/symbols.json` — адресные метаданные. Никаких новых полных игровых файлов или извлечённых ресурсов в этой ветке нет. Эти исходники не означают, что публичный checkout самодостаточен без локальных входов.

Приватный полный комплект восстановления: `Cyber-Cop_v36_test02.zip`, SHA и входные файлы — `docs/input_manifest.json`. Он ранее передан пользователю; не загружать этот ZIP в GitHub. Внутри `rebuild/` есть локальные входы для воспроизведения. Не путать его с публичными исходниками.

Старая публичная сборка v35c: `sources/BUILD_RU.md`, `sources/build_v35.py`. Она требует оригинальные Cyber-Cop и Corporation. В v36 местонахождение базы и таблиц символов иное: `v35c/Cyber-Cop_v35c.bin`, `v35c/symbols.json`, `v34/symbols.json` относительно корня исследовательского workspace.

## Неопубликованные входы v36
- Amiga: `amiga3/mission.bin`, `amiga_research/mission.adf` — распакованный executable и диск Mission.
- `amiga_research/maps.json`: результат двух кампаний; генератор `amiga_research/maps.py` использует `unpack.py` и конкретные IPF-прессинги. Это данные карт, в GitHub их не копировать.
- `v36/original_lamps.json`: производные координаты добавляемых ламп; не входит в публичный checkpoint.
- `v36/st_items_pixels.json`: декодированная графика листа Atari ST, не текстовая конфигурация. Не публиковать несмотря на расширение JSON. Источник — распакованный `ILGJ.bin`; скрипт `mission_port36/unpack_st.py` опирается на локальные loader/resources и `st2/deice.py`.
- Некоторым сравнениям нужны `amiga3/d2.bin`, `amiga_research/d2.adf`; тестам — приватные Gens states и старый ROM. Файлы проверять по hash manifest, не искать замену с тем же именем в интернете.
- Отдельные исследовательские скрипты имеют зависимости от старого workspace (например, atlas36/mission_objects). Это исторические инструменты, не обязательные шаги сборки. Не запускать весь каталог подряд.

## Команды
Из корня восстановленного исследовательского workspace:

```sh
python3 v36/build.py
python3 v36/test_fixes02.py
```

Нужны Python3, Capstone, Pillow; CPU-тестам Unicorn (проверены на 2.1.4). В исходной среде пакеты из `st2/deps` подключались через `PYTHONPATH=st2/deps`, но этот каталог зависимостей не распространяется. Сборщик сам использует Capstone только для ограниченного известного диапазона AI; это часть релокации, а не новый полный анализ ROM.

Выход — локальный `v36/Cyber-Cop_v36_WORK_IN_PROGRESS.bin`. Сборщик обновляет symbols.json и sprites.json; первый — метаданные адресов, второй — генерируемые метаданные кадров (не требуется коммитить автоматически). Данные ресурсов создаются из локальных файлов при сборке.

Сборка из приватного архива test02 уже проверена отдельно: выход побайтово совпал с переданным ROM. SHA-256 выхода зафиксирован в manifest. При последующем коммите только документации повторять её не нужно.

Скриншот offscreen может быть вертикально сжат; для pixel analysis предпочтительно декодировать native VRAM/framebuffer. Не переносить этот дефект скриншота в геометрию игры.

## Перед продолжением
1. Прочитать DEVELOPMENT_STATE и тематический документ.
2. Сопоставить SHA исходников/входов с текущим checkpoint; исходный ROM не менялся — повторно извлекать данные не нужно.
3. Восстановить только недостающие приватные входы; не копировать их в публичный индекс Git.
4. Выполнить требуемый локальный анализ/тест, сохранить вывод в документацию.
5. Проверить только предлагаемые к коммиту файлы. Записать результат теста и коммитить в wip.

Лимит чата может остановить работу до следующего checkpoint. Эти правила уменьшают размер возможной потери; они не обеспечивают фоновую работу или гарантированный коммит в момент принудительной остановки.
